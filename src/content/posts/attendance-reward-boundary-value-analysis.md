## 상황

출석 리워드는 다음과 같습니다.

- **조건:** 7일 연속 출석합니다.
- **광고 제거:** 수령일을 포함해 8일입니다.
- **수령 기한:** 완주 당일부터 7일 뒤까지입니다.

보너스로 자동 출석권을 제공합니다. 결석하면 자정 이후에 출석권으로 빠진 날을 채웁니다.

리워드 수령 후 7일 연속 출석하면 자동으로 연장됩니다.

- **직접 출석:** 완주 즉시 연장됩니다.
- **자동 출석:** 자정 이후 결석을 채우면서 연장됩니다.

## 문제

리워드 수령 시점에 따라 연장 결과가 달랐습니다.

- **완주 당일 수령:** 연장됐습니다.
- **이틀 뒤 수령:** 연장이 누락됐습니다.

수령 기한을 지켰고 출석도 채웠지만 연장되지 않았습니다.

다음 경우도 확인해야 했습니다.

- 완주 하루 뒤 수령
- 수령 기한 직전 수령
- 마지막 날 자동 출석

테스트를 나누는 기준이 필요했습니다.

## 원인

완주 시점에 리워드 만료를 판단한 것이 원인이었습니다.

- **완주:** 연속 출석 7일
- **광고 제거:** 수령일 포함 8일

수령이 늦어지면 만료일도 늦어집니다. 완주일과 만료일을 따로 판단해야 했습니다.

수령일은 자정에 바뀝니다. 8월 23일 완주 후 **23일 23:59:59 수령과 24일 00:00:00 수령**을 비교했습니다. 1초 차이로 만료일이 하루 늦어집니다. 광고는 만료일 다음날 00:30 직전까지 숨깁니다.

![23일 23:59:59와 24일 00:00:00 수령에 따른 만료일 비교](@/assets/images/attendance-reward-boundary-value-analysis/01-claim-date-shift.png)

이틀 뒤 수령한 사례입니다.

| 입력: 완주일 | 행위: 수령일  | 결과: 광고 제거 날짜 |
| ------------ | ------------- | -------------------- |
| 8월 23일     | 8월 23일 수령 | 8월 23 ~ 30일        |
| 8월 23일     | 8월 25일 수령 | 8월 25일 ~ 9월 1일   |

### 명세에서 구획과 경계를 찾았습니다

Maurício Aniche의 [『Effective Software Testing: A developer’s guide』](https://www.manning.com/books/effective-software-testing) 2장을 참고했습니다. 이전에 쓴 [명세 기반 테스트 정리](https://github.com/this-is-spear/blog/blob/main/data/blog/books/effective-software-testing/2.mdx)를 이번 문제에 적용했습니다.

![Maurício Aniche의 Effective Software Testing 책 표지](@/assets/images/attendance-reward-boundary-value-analysis/effective-software-testing-cover.jpg)

표지 출처: [Simon & Schuster 공식 도서 소개 · Manning 출판](https://www.simonandschuster.com/books/Effective-Software-Testing/Mauricio-Aniche/9781633439931)

명세 기반 테스트는 요구사항에서 테스트를 찾는 방법입니다.

1. **요구사항 이해:** 입력과 기대 결과를 정합니다.
2. **구획과 경계 분석:** 같은 방식으로 처리되는 입력을 묶고 대표값과 경계값을 고릅니다.
3. **테스트 구현:** 선택한 값으로 테스트를 자동화합니다.

놓친 조건을 발견하면 앞 단계로 돌아가 보완합니다.

**구획**은 같은 방식으로 처리되는 입력 묶음이고, **경계**는 결과가 달라지는 지점입니다.

- 출석이 6일에서 7일이 되는 순간
- 수령 기한이 끝나는 순간
- 광고 제거가 끝나는 순간

이틀 뒤 수령은 버그가 발생한 조건입니다. 경계값인지는 수령일에 따른 완주일과 만료일의 관계를 확인해야 합니다.

## 해결

### 변수와 경계를 정했습니다

변수들이 서로 영향을 줘서 풀기 어려웠습니다. 수령일이 바뀌면 만료일이 달라지고, 출석 방식에 따라 완주 기록 시각도 달라집니다.

다른 조건을 고정하고 **변수 하나의 경계**부터 확인했습니다. 그다음 **변수를 조합**했습니다. 표는 **입력 → 행위 → 결과** 순서입니다.

- **입력:** `출석 일수`, `수령 여부` 등 바꿀 값
- **고정 조건:** `만료일 = 8월 23일` 등 유지할 값
- **행위:** 동작과 실행 시각
- **결과:** 광고 표시, 수령 가능 여부 등

예를 들어 **출석 6일·7일 × 유예 종료 직전·정각**은 네 가지 조합입니다.

입력은 **행위 직전 값**입니다. 연장 후에는 새 도전의 출석 일수로 표시합니다. 실제로 가능한 조합을 골랐습니다.

| 변수                               | 경계값                             | 확인할 결과                |
| ---------------------------------- | ---------------------------------- | -------------------------- |
| 출석 일수                          | 6일 / 7일                          | 수령 자격                  |
| 리워드 수령 여부                   | 수령 전 / 수령 후                  | 출석·출석권 획득 가능 여부 |
| 수령 요청 시각                     | 수령 기한 1초 전 / 정확히 기한     | 수령 가능 여부             |
| 리워드 만료일과 처리 날짜          | 만료일 당일 / 다음날 / 이틀 뒤     | 클릭·자동 연장 가능 여부   |
| 광고 제거 종료 시각                | 다음날 00:29:59 / 00:30:00         | 광고 표시 여부             |
| 출석 후 지난 시간과 보유 출석권 수 | 4시간 직전 / 4시간 경과, 1장 / 2장 | 출석권 획득 가능 여부      |
| 클릭과 자동 처리 순서              | 클릭 먼저 / 자동 처리 먼저         | 완주 확인 시점과 연장 결과 |

글에서는 **00:29:59와 00:30:00**처럼 초 단위로 표시했습니다. 테스트는 경계 1ms 전과 정각을 비교합니다.

표의 결과는 다음 기준으로 읽습니다.

- **기준:** [수정 PR](https://github.com/est-aplus/altools-adfree-reward-api/pull/63)의 코드와 테스트를 반영했습니다.
- **안내:** 코드값을 풀어 쓴 표현입니다.

- 마지막 날 직접 클릭: 즉시 연장
- 마지막 날 자동 출석: 24일 자정 이후 출석 보완 → 연장

- 18 ~ 23일: 6일 출석

**고정 조건**

- 연장 기록: 없음

**완주 기록이 있어도 7번째 출석 날짜가 만료일 뒤라면 연장하지 않습니다.** 자동 처리를 반복해도 출석권 사용과 연장은 중복되지 않습니다.

### 수정한 규칙

- **수령 기한:** 기록 시각 대신 7번째 출석 날짜로 계산합니다. 직접·자동 출석 모두 23일 완주라면 31일 00:00에 끝납니다.
- **연장 자격:** 광고 제거 중이고 7번째 출석 날짜가 만료일 이내여야 합니다. 자동 연장도 출석 날짜를 확인합니다.
- **수령 당일:** 새 출석은 막고 다음날부터 시작합니다. 그날 직접 출석한 기록이 있으면 4시간 뒤 출석권을 얻을 수 있습니다.
